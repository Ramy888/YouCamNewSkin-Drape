Fable’s pick, **Drape**, is smart but dangerously expensive and a little too “TikTok trend translated into API demo.”

The biggest weakness is unit cost. Facial Color Tones is 20 units before the app has even shown a shoppable transformation. Then Drape proposes 4 Clothes VTO calls, so the core demo is ~28–30 units/session. With a 1,000-unit budget, that leaves little room for failed calls, testing, judges, friends, retries, and video production. For a one-dev hackathon build, the winning concept should not depend on the most expensive API being both accurate and visibly meaningful on camera.

Second: the “wrong colors grey the face out” wow may not actually read. If the app locally hue-shifts fabric, the judge may see a design trick rather than a YouCam-powered breakthrough. If the effect is subtle, it becomes color-theory homework. If it is exaggerated, it feels fake. The video hook depends on a visible before/after that YouCam may not directly produce.

Third: Drape risks being judged as “seasonal color analysis + VTO,” which is already a known consumer pattern. It is differentiated from Try & Buy, yes, but not necessarily “another planet.” The hijab workaround is clever, but a recolored drape overlay is not the same as true hijab try-on; if presented too boldly, it exposes the API gap again.

What Fable got genuinely better than me: **Drape has stronger technical integration**. One measurement drives both fashion colorways and beauty shades, which is deeper than my Return-Proof Cart if mine is only scripted critique. Fable also found a sharper MENA-friendly wedge: color around the face matters intensely for hijab, makeup, and occasionwear, and it avoids pretending there is a hijab API.

Merged final concept: **The Regret Mirror**

Hook: The shopper tries one occasion outfit. The app flashes three “future return reasons” directly on the image: “washes out your face,” “lip clashes with fabric,” “necklace disappears.” Then it repairs the entire look live into a cart that is visibly better.

Mechanism: Combine Drape’s color logic with my regret-prevention framing. Do not sell “AI stylist.” Sell “visual return insurance.” The system generates a bad cart and a fixed cart, using face tone/color rules plus VTO proof. The alien part is that the mirror argues against the purchase before selling the better one.

API chain:  
Cheap judge/demo mode: Fitzpatrick skin type 2 + Clothes VTO 2 + Makeup VTO 1 + Necklace/Earrings 1–2 = **6–7 units/session**.  
Premium optional mode: Facial Color Tones 20 once per user, then Clothes 2 + Makeup 1 + Jewelry 1–2 = **24–25 units first session**, **4–5 units after cached tone**.

60-second video:
0–5s: Arabic/English store, shopper uploads selfie and picks a satin emerald dress.  
5–15s: Clothes VTO renders it. The app stamps: “Return risk: color drains warmth from face.”  
15–25s: It tries the common mistake: cool pink lipstick + tiny silver necklace. Makeup/Jewelry VTO shows the clash.  
25–40s: “Fix cart” applies warmer lip, gold earrings/necklace, alternate dress color or accessory. Same face, same pose, visibly more coherent.  
40–50s: Split-screen: “Cart likely to regret” vs “Cart approved.”  
50–60s: Add full repaired bundle to cart. Tagline: “Don’t recommend products. Prevent returns.”

Cheapest de-risk: **7 units**. Run Fitzpatrick (2), one Clothes VTO (2), one Makeup VTO (1), one Earrings/Necklace VTO (1–2). If the visual difference reads on a phone recording, the concept works. Only spend the 20-unit Facial Color Tones call after that.

The owner must NOT build: a chatbot or “AI stylist” that recommends outfits. Judges will see 50 of those, and Kostuma already proved outfit-plus-makeup is not enough.
